# AgentTag

仿照 Claude Tag 做的飞书版团队 AI 助手：机器人作为成员加入飞书群，群里任何人 @ 它即可提问或派活，它在那条消息的话题里回复。

当前是阶段 3.5（接 MCP），已接上飞书云文档、联网搜索、代码仓库，以及通过 MCP 接入的运维系统 aiops：

- **飞书云文档**：群里贴一个飞书文档链接（新版文档或知识库页面），@ 机器人让它看、总结、按文档回答问题；也可以让它把讨论整理成一篇新文档，或者改已有的文档（追加、在某段前后插入、替换、删除）。新建的文档自动共享给本群（可编辑）和发起人（可管理），回答里附上链接。机器人要先有这篇文档的权限，见下面「飞书云文档的权限」。
- **群记忆**：机器人给每个群记下长期有用的信息（项目背景、做过的决定、团队约定、成员分工和偏好），群里任何话题、隔多少天再 @ 它都能用上。可以直接说「@机器人 记住：……」「你记得什么」「忘掉 #3」；对话里出现决定、约定这类信息时它也会主动记，并在回答末尾说一句「已记住：……」。
- **补漏轮询**：同一个飞书应用如果还有别的程序连着长连接，飞书会把一部分 @ 推给那个程序，机器人就收不到。机器人每 10 秒读一次白名单群和它参与过的话题里的新消息，把没从事件收到的 @ 补上处理（晚几秒回复），日志里记一行「补漏：事件没送到，由轮询补上」。30 分钟内补上 2 条以上（事件过了 1 分钟还没到），机器人会在群里发一条补漏报警，1 小时内不重复。
- **群记忆每日备份**：每天把所有群的记忆复制一份到 `data/backup/memory/<日期>/`，保留最近 14 天。
- **话题里接着聊**：在机器人回复的话题里再 @ 它追问，它会带着话题里之前的消息回答。
- **联网搜索**：要查新闻、版本、价格这类最新信息时，机器人用百炼模型自带的联网搜索查，回答里附上来源链接。每次搜索会多调一次百炼模型，另按百炼的联网搜索计费。
- **代码仓库**（公司自建 GitLab，也支持 GitHub）：配好允许的仓库后，可以在群里问代码的问题（机器人拉下代码来搜、来读，回答带分支、文件和行号；模型没读代码就说仓库里的内容时，程序会把这版回答打回去，让它先查再答）。默认看仓库的默认分支，在群里说「看 aiops 分支」它就切过去，这个话题后面都用这个分支；默认分支上找不到、或者不知道在哪个分支时，它会在最近有提交的几个分支上一起搜。也可以让它改代码、开合并请求。它只推到自己新建的 `agenttag/…` 分支，合并请求开到话题当前的分支，不会推到已有的分支，也不会合并；在同一个话题里接着让它改，会推到同一个合并请求。它不在服务器上运行代码和测试。
- **线上排查（aiops，通过 MCP 接入）**：群里 @ 机器人「xx 服务最近一小时报什么错」「诊断一下 xx 服务」「现在有哪些告警」「xx 的 Pod 为什么重启」「接着查案例 #N」，它调团队的 aiops 系统查 K8s、Loki 日志、Prometheus 指标和 Tempo 链路，按查到的证据回答。排查服务问题时先用 aiops 的一键诊断，再补查几次；一次任务里 aiops 工具最多调 10 次，同样的参数不重复调。不说命名空间时由 aiops 按服务名自己定位，同名服务在几个命名空间时机器人会先问查哪个。模型只能用 20 个只读工具。每次调用都记审计日志（谁问的、哪个群、哪个工具、参数摘要、结果大小、用时），因为 aiops 那边用的是共享令牌，不知道是谁让机器人查的。
- **团队经验库（飞书多维表格）**：所有群共用，存有人确认过的结论，分排查经验、应答卡、数据口径、需求结论几类，编号写成 K1、K2。
  - 每次提问前，程序先拿问题去经验库查一次（关键词加百炼向量模型按意思查；接了 aiops 时 aiops 自带的经验库也查），查到相近的就附给模型。回答里写「参考经验 K3」，但还是要按这次查到的证据下结论。这一步最多等 8 秒：哪边没查完就不等它，向量没算完就只按关键词，不耽误回答。
  - 只有在群里明确说「沉淀到经验库」这类话时，机器人才起草一条，发一张确认卡片。写权限名单（`WRITE_ALLOWED_USERS`）里的人点「保存」，程序才按卡片上的内容写进去；别人点无效，24 小时没人点就失效。
  - 经验库里有很像的经验时，卡片上会提示。改错就起草新的一条替换旧的；删就是归档。都走确认卡片。新的一条在表格的「取代的经验」列里记下替换的是哪条；旧的那条还没归档时（比如归档那步没做成），别的卡片不能再替换它，免得两条新的同时有效。
  - 排查经验保存时同时写一份到 aiops 经验库，告警自动排查和 Open WebUI 也能用上；归档时两边一起归档。aiops 连上了却没有保存、归档经验的工具（版本旧、没配 MySQL）时只存团队经验库，卡片上也不说会同步。
  - 草稿里有令牌、密码这类密钥时，程序不让发卡片。
  - 第一次保存时机器人自己建一张多维表格「AgentTag 经验库」：白名单群只读，写权限名单里的人可以直接在表格里看、筛选和修改（可编辑）。只有机器人能加、移除协作者，链接分享和分享到组织外都关掉，所以名单外的人打不开，名单里的人也没法再共享给别人；这一步没设好之前（比如还没开权限）先不共享给任何人。表格链接在保存结果里，建表时日志里也记一行。共享跟着白名单群和写权限名单走：启动时和每次保存时补上没共享成的（比如还没开权限）、撤掉移出名单的；别人在飞书里手动加的协作者不动。
  - 点「保存」后结果没传回来、卡片提示失败再点一次时，不会存成两条（每张卡片有一个草稿编号，写在表格的「草稿编号」列里）。
  - 存进经验库以后，同步 aiops、记 aiops 编号、归档被取代的旧经验这几步有没成功的，卡片变成「已存进经验库，还有没做成的」，列出没做成的，可以点「再试一次」补上：做完的不会再做一遍（aiops 那边先按出处找有没有已经存进去的那条）。同步到 aiops 的是表格里这一行现在的内容，再试之前在表格里改过的也照改过的同步，改进去的密钥不会同步过去；再试之前在表格里归档了它或者改成别的类别，就不再同步。取代旧经验时，新的没进 aiops 就不归档 aiops 里旧的那条。点「不用了」或者超过 24 小时就不再试。机器人重启后这张卡片就不能再试了，没做成的要手动处理。
- **多步工具调用**：模型可以自己决定调用工具、分几步完成任务。目前有联网搜索、读取网页、飞书云文档、代码仓库、群记忆，以及通过 MCP 接入的工具（aiops）。
- **进度卡片**：每个任务先在话题里发一张卡片，实时显示正在执行的步骤，结束后收成一行「已完成 · N 步 · 用时」，回答另外发在话题里。
- **深度思考**：为了回答快，默认不开模型的思考模式。遇到难题（排查复杂问题、设计方案、改代码前的分析），在问题里写「深度思考」「仔细想想」或「认真分析」，这一次会打开思考，慢一些但想得更周全；最多想 4000 token（大约两分钟），超过就直接回答。
- **中途停止**：点卡片上的「停止」按钮，或在话题里 @ 机器人说「停止」。
- **不重复处理「同时发送到群」**：在话题里 @ 机器人时勾了「同时发送到群」，群里会多出一条一样的消息。同一个人 10 秒内发的同一句话只处理一次（话题里那条优先），写文档这类操作不会做两遍，日志里记一行「跳过重复的提问」。
- **知道自己叫什么**：机器人在飞书里的名字（比如「飞书 CLI」）会写进提示词。

长连接模式只需要能访问公网，不需要公网地址，内网服务器或本地电脑都能跑。

模型通过 OpenAI 兼容接口调用，默认接阿里云百炼。接口地址、Key、模型 ID 都从环境变量读，换千问、Kimi、GLM 等模型不用改代码。

## 工作方式

```
飞书群 @机器人
  → 飞书长连接（WebSocket）推送 im.message.receive_v1
  → 飞书 SDK Channel：识别 @、按消息 id 去重、丢弃过期重推，事件处理立即返回（飞书要求 3 秒内确认）
  → bot.ts：只处理群白名单里的群，取出问题（去掉 @机器人，其他 @ 换成名字）；「停止」指令直接停任务
  → tasks.ts：同一话题里的任务排队依次执行，不同话题并行
  → 在话题里发进度卡片（带停止按钮）
  → history.ts：读取话题里之前的消息作为上下文
  → memory.ts：读出这个群的记忆写进系统提示词，并给这次任务配上只能读写这个群记忆的工具（tools/memory.ts）
  → 给这次任务配上飞书云文档工具（tools/docs.ts），新建的文档共享给当前群和发起人
  → mcp.ts：配上 MCP 服务的工具（如 aiops），调用次数按任务算；服务端的使用说明写进系统提示词
  → tools/knowledge.ts：先在团队经验库（和 aiops 经验库）里查相近的经验写进系统提示词，再配上查经验、起草经验的工具
  → agent.ts：工具循环。问模型 → 模型要调工具就执行（tools/）并把结果交回 → 直到给出回答；每一步更新进度卡片
  → 卡片改成「已完成」，回答以富文本（Markdown）发到话题里，过长时拆成多条

点卡片上的「停止」→ 飞书长连接推送卡片回调 card.action.trigger → 中止对应任务（正在进行的模型请求和工具调用一并取消）
点经验库确认卡片上的「保存」「归档」→ 同一个卡片回调 → 写权限名单里的人点的才执行，按卡片上的内容写进多维表格（排查经验再同步到 aiops）
```

## 目录

| `src/config.ts` | 从环境变量读取并校验配置 |
| `src/bot.ts` | 处理一条 @ 消息：停止指令、进度卡片、跑工具循环、回复到话题；处理截断、内容审核和报错；处理卡片上的停止按钮 |

| `src/knowledge-aiops.ts` | aiops 自带的经验库：回答前检索，排查经验同步过去，归档 |

| `prompts/mcp/` | MCP 服务在飞书群里的使用说明（`aiops.md`），开了它的工具时写进系统提示词。改完不用重启，每 10 分钟重新读一次 |
| `src/tools/` | 工具。`tool.ts` 是工具接口（以后 MCP 工具也实现它），`fetch-url.ts` 是读取网页工具，`memory.ts` 是记忆工具（记下、修改、删除、查找），`docs.ts` 是飞书云文档工具（读、新建、改），`web-search.ts` 是联网搜索，`code.ts` 是代码仓库工具（列出和切换分支、列文件、读、搜、改、看改动、开合并请求） |
| `src/repo.ts` | 代码仓库：每个话题一份浅克隆的工作目录，读写都限制在仓库里（不跟着符号链接出去），读别的分支时按需浅拉那个分支、直接读 git 里的对象，不动工作目录，提交推到机器人自己的分支再开合并请求；代码平台（`CodeHost`）有 GitLab 和 GitHub 两种 |
| `src/docs.ts` | 飞书云文档：解析文档和知识库链接、调文档接口、按块插入/替换/删除、新建后共享给群，把接口错误翻译成能转告的话 |
| `src/doc-render.ts` | 把文档的块转成 Markdown 给模型读（标题、列表、待办、代码、引用、表格、链接） |
| `src/memory.ts` | 群记忆：每个群一个 JSON 文件，写入排队、原子替换；写进提示词的格式和字数上限；关键词检索 |
| `src/history.ts` | 读取话题上下文：优先从飞书读整个话题，读不到时用本地记下的问答 |
| `src/feishu.ts` | 用到的飞书读接口（读话题消息、读单条消息） |
| `src/tasks.ts` | 进行中的任务：同话题排队、按任务/话题/群停止 |

| `src/alarm.ts` | 补漏报警：补上的 @ 多了就在群里提醒一次；事件晚到的不算 |
| `src/backup.ts` | 群记忆每日备份，按天存放，超过保留天数的删掉 |
| `src/progress.ts` | 进度卡片的样子，以及合并、限速地更新卡片 |
| `src/prompt.ts` | 系统提示词（机器人名字、当前时间、工具使用规则） |
| `src/llm.ts` | 模型调用层：`ChatModel` 接口和 OpenAI 兼容实现（含工具调用），换模型服务只动这里或环境变量 |

## 第一步：在飞书开放平台创建应用

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建「企业自建应用」。
2. **添加应用能力** → 添加「机器人」。
3. **权限管理** → 开通以下权限：
   - `im:message.group_at_msg:readonly`（接收群聊中 @ 机器人消息事件）
   - `im:message:send_as_bot`（以应用的身份发消息，也用来更新进度卡片）
   - `im:message.group_msg`（获取群组中所有消息，敏感权限，需要管理员审核）：用来读取话题里之前的消息。不开也能用，但追问时机器人只记得之前 @ 它的问题和它的回答，看不到话题里其他人没 @ 它的发言，而且重启后就忘了。开了以后机器人会收到所在群的所有消息事件，程序只处理 @ 它的，其余直接丢弃。
   - `im:resource`（获取与上传图片或文件资源）：下载提问里的截图交给模型看。不开时机器人看不到图片，会请对方把图片里的文字贴出来。
4. **凭证与基础信息** → 记下 App ID 和 App Secret，填进 `.env`（见第三步）。
5. **版本管理与发布** → 创建版本并发布，让机器人和权限生效。
6. 按第三步把程序跑起来，保持运行。
7. **事件与回调** → 事件配置 → 订阅方式选「使用长连接接收事件」并保存（程序没在运行时保存会失败）→ 添加事件「接收消息」`im.message.receive_v1`。
8. 可选，用飞书云文档和团队经验库时开：**权限管理** 里再开通下面这些。可以用「批量导入」粘贴 `{"scopes":{"tenant":["docx:document","docx:document.block:convert","wiki:wiki:readonly","docs:permission.member:create","docs:permission.member:update","docs:permission.member:delete","docs:permission.setting:write_only","drive:drive.metadata:readonly","bitable:app"],"user":[]}}`，个别权限名在你的后台搜不到时去掉它，缺什么机器人用到时会报出来。
   - `docx:document`（查看、编辑新版文档）：读文档、新建文档、改文档
   - `docx:document.block:convert`（把 Markdown 转成文档块）：写入内容
   - `wiki:wiki:readonly`（查看知识库）：读知识库链接背后的文档
   - `docs:permission.member:create`（添加文档协作者）：新建的文档共享给群和发起人，不开的话新建的文档谁都打不开
   - `docs:permission.member:update`（更新协作者权限）、`docs:permission.member:delete`（移除协作者）：团队经验库的多维表格跟着白名单群和写权限名单走，名单里去掉的群或人要撤掉权限，权限变了要改。不开的话撤不掉，被移出写权限名单的人还能直接改表格，日志里会有警告写明缺哪个权限
   - `docs:permission.setting:write_only`（更新云文档权限设置）：把团队经验库的多维表格设成只有机器人能加、移除协作者，关掉链接分享。不开的话机器人不把表格共享给任何人（群里打不开表格，检索和保存照常），免得拿到权限的人再共享出去，日志里有警告；开了以后下次启动或保存时自动共享
   - `drive:drive.metadata:readonly`（查看文件元数据）：拿新建文档的链接。不开也行，机器人会用群里贴过的文档链接的域名拼
   - `bitable:app`（查看、评论、编辑和管理多维表格）：团队经验库。不开时回答前的检索照常（还没有表），保存经验时卡片上会提示缺这个权限。建表后共享给群、撤掉或改权限要用上面三个 `docs:permission.member:*`，限制谁能共享要用 `docs:permission.setting:write_only`
9. **事件与回调** → 回调配置 → 订阅方式选「使用长连接接收回调」并保存 → 添加回调「卡片回传交互」`card.action.trigger`。不配的话点进度卡片上的「停止」会报错，但在话题里 @ 机器人说「停止」照样能停。
10. 再创建一个版本并发布，让事件和回调订阅生效。以后改权限、事件或回调都需要重新发布。
11. 在飞书里建一个测试群 → 群设置 → 群机器人 → 添加这个机器人。

## 第二步：开通阿里云百炼 API Key

1. 登录 [阿里云百炼控制台](https://bailian.console.aliyun.com)，开通服务。
2. 创建 API Key，填进 `.env` 的 `MODEL_API_KEY`。要用**按量计费的普通 API Key**，不要用 Coding Plan 的 Key，它的条款不允许用作应用后端。
3. 可选：百炼为北京地域推出了业务空间专属域名，建议把 `MODEL_BASE_URL` 设为 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`（WorkspaceId 在控制台查看）。不设时用默认的 `https://dashscope.aliyuncs.com/compatible-mode/v1`。

## 第三步：运行

需要 Node.js 22 或更高版本。

```bash
npm install
cp .env.example .env   # 填入 FEISHU_APP_ID、FEISHU_APP_SECRET、MODEL_API_KEY
npm run dev            # 开发模式，改代码自动重启
```

看到 `飞书长连接已建立，机器人「…」` 就说明连上了。完成第一步剩下的事件订阅和发布后：

1. 在测试群里 @ 机器人随便说一句。机器人默认不响应任何群，终端会打出 `忽略白名单外的群 chat=oc_xxx`。
2. 把这个 `oc_xxx` 填进 `.env` 的 `FEISHU_ALLOWED_CHAT_IDS`，重启程序。
3. 再 @ 机器人问个问题：话题里先出现一张进度卡片，接着是回答。
4. 在这个话题里再 @ 机器人追问，它会接着前面的内容回答。
5. 在群里 @ 机器人说「记住：我们每周三发版」，再另起一条 @ 它问「我们哪天发版？」，它会用上刚才的记忆。
6. 让它做件需要几步的事，比如「@机器人 读一下 https://… 和 https://… 这两篇，对比一下」，卡片上会列出每一步；中途可以点「停止」。

机器人如果也在告警群等业务群里，只要不把那些群加进白名单，它在那里被 @ 也不会回应。

部署时：

```bash
npm run build
npm start
```

| `FEISHU_DOMAIN` | 否 | `feishu`（默认）或 `lark`（海外版） |

| `KNOWLEDGE` | 否 | 团队经验库，默认 `on`，填 `off` 关掉（回答前不查，也没有起草经验的工具） |
| `KNOWLEDGE_BITABLE` | 否 | 用哪张多维表格存经验，填打开那张数据表时浏览器里的链接（`https://xxx.feishu.cn/base/…?table=tbl…`）。不填时第一次保存经验时机器人自己建一张，记在 `<DATA_DIR>/knowledge/bitable.json`。指定的表机器人不管共享：谁能看、谁能改在飞书里自己设，白名单群和写权限名单变了也不会跟着改。机器人自己建的表不要填在这里（填了就不再按名单撤销权限，而这张表只有机器人能管协作者），见下面「经验库表格的记录文件」。指定的表缺哪些列，机器人第一次写入前自动补上 |
| `KNOWLEDGE_EMBEDDING_MODEL` | 否 | 经验库按意思检索用的向量模型，和主模型用同一个服务和 Key。百炼默认 `text-embedding-v4`，别家服务不配时只按关键词检索，填 `off` 也只按关键词 |

**换模型**：百炼上的其他模型（千问其他型号，以及 Kimi、GLM、DeepSeek 等第三方模型）只需改 `MODEL_ID`，模型 ID 在百炼控制台的模型列表里查。要换到别家的 OpenAI 兼容接口，再改 `MODEL_BASE_URL` 和 `MODEL_API_KEY`。

## 常见问题

- **启动时报「连接飞书失败」**：App ID / Secret 不对，应用还没添加机器人能力、没发布版本，或者服务器访问不了 `open.feishu.cn`（内网服务器需要放行出网）。
- **@ 了机器人没反应**：先看终端日志。出现 `忽略白名单外的群` 说明这个群还没加进 `FEISHU_ALLOWED_CHAT_IDS`。什么日志都没有的话，检查长连接订阅和 `im.message.receive_v1` 事件是否已添加并发布、机器人是否在群里，以及有没有别的程序（比如调试用的监听脚本，或同一个应用的其他服务）也用这个应用连着长连接：飞书只把每个事件推给其中一个连接，事件会被分走。
- **回复「连不上模型服务」**：运行环境访问不到 `MODEL_BASE_URL`，检查内网服务器的出网策略。
- **回复「模型服务返回错误」**：多半是 `MODEL_ID` 写错或该模型没开通，终端日志里有模型服务返回的原始报错。
- **回复「被内容审核拦下」**：百炼对输入输出做内容审核，换个说法即可。
- **追问时机器人不记得话题里其他人说的话**：没开 `im:message.group_msg` 权限，启动后第一次追问时日志里会有「读取话题历史失败」。开通权限并发布新版本即可，不用重启。
- **点「停止」提示出错**：没在回调配置里用长连接订阅 `card.action.trigger`，或者配了没发布新版本。
- **进度卡片没出现，但回答正常**：日志里会有「发送进度卡片失败」和飞书返回的原因。常见原因是飞书客户端版本太旧，不支持卡片 JSON 2.0。
- **机器人说没有文档的权限**：飞书里应用默认看不到任何文档。让文档所有者在文档右上角「…」→「更多」→「添加文档应用」里加上机器人，或者把文档分享给机器人所在的群（添加群为协作者）。知识库页面同理。
- **机器人说缺少飞书应用权限**：按回答里给出的权限名（飞书的报错里带着申请链接）在开发者后台开通，然后发布新版本，不用重启。
- **搜索失败或没有来源**：搜索走百炼原生接口（和 `MODEL_BASE_URL` 同一个域名的 `/api/v1/...`），要能访问它；模型要支持联网搜索（千问 Max、Plus 等支持，第三方模型一般不支持）。千问 3.5 以后的多模态模型要走多模态接口，第一次报「url error」后会自动换过去；两个接口都报「url error」时，设 `WEB_SEARCH_MODEL=qwen-plus` 试试。回答里说「没有返回搜索来源」时，多半是模型没真的去搜，换 `WEB_SEARCH_MODEL` 试试。
- **回复慢，想知道时间花在哪**：日志里每轮模型调用记一行（`模型第N轮 用时 输入 输出 其中思考 → 调用哪些工具 / 给出回答`，单位是 token），每次工具调用记一行用时，工具失败时记下原因。时间多半花在模型输出上：回答或写进文档的内容越长越慢；「其中思考」很大说明模型开着思考模式。
- **代码仓库访问不了**：启动日志里每个仓库有一行「代码仓库 xxx：能访问，角色 Developer」或「代码仓库 xxx 访问不了：原因」。GitLab 对看不到的私有项目也回 404，所以「找不到项目」多半是令牌的账号不是项目成员、用了别的项目的项目访问令牌，或者 `CODE_REPOS` 里的路径和网页地址栏里的不一样。
- **机器人说「回答里引用的文件、行号或提交号在查到的代码里找不到」**：模型引用了这次工具结果里没有的文件或提交号，打回重做一次后还是这样，回答就没有发出，日志里有「还是引用了没查到的代码位置，没有发出」和那些路径。多半是问到的服务代码不在 `CODE_REPOS` 里：要让机器人读这个服务的代码，请这个仓库的 Maintainer 把机器人账号加成 Developer，再把仓库加进 `CODE_REPOS` 并重启。
- **代码仓库工具报 git 失败**：服务器要装 git（2.31 以上），并能访问 `GITLAB_URL`（GitLab 在公司内网时，服务器要能连进去）。令牌要能访问 `CODE_REPOS` 里的项目并推分支、开合并请求。GitLab 用的是自签名证书时，把公司的根证书放到服务器上，在 `.env` 里设 `GIT_SSL_CAINFO` 和 `NODE_EXTRA_CA_CERTS` 指向它。每个话题拉的代码在 `data/workspaces/<话题>/` 下，3 天没用自动删掉。
- **aiops 工具没出现**：启动后日志里应该有一行「MCP aiops：已连上 …，服务端 29 个工具，开了 20 个」。看到「MCP aiops 连不上：HTTP 404，令牌或地址不对」时检查 `MCP_AIOPS_TOKEN` 和 `MCP_SERVERS` 里的地址（aiops 令牌不对时回 404，不是 401）；其他原因多半是服务器访问不了 aiops 的地址。连不上时机器人照常回答别的问题，按 30 秒、1 分钟、2 分钟、5 分钟的间隔自动重试。每次 aiops 调用在日志里记一行「MCP 调用 aiops.工具名 chat=… sender=… 参数=… 结果=…字 用时=…」。
- **机器人说看不到图片**：日志里有「识别图片 0/1 张」时，往上找原因。「下载图片失败」多半是没开 `im:resource` 权限（开通后发布新版本，不用重启）；「识别图片失败」多半是 `MODEL_VISION_ID` 指的模型不能看图，换成 `qwen3-vl-plus` 这类视觉模型试试。日志里是「没配看图模型」时，检查 `MODEL_VISION_ID` 是不是设成了 `off`。一次提问最多识别 4 张图（提问里的在前，然后是话题里最近的），识别过的图会记住，话题里追问时不再重新识别。
- **读取网页失败**：服务器要能访问公网。出于安全考虑，工具不会访问内网、本机和云服务器元数据地址。
- **@ 了有时回有时不回**：多半是同一个飞书应用还有别的程序连着长连接，把一部分事件分走了。补漏轮询会把这些 @ 补上，日志里出现「补漏：事件没送到」就是这种情况，补上的多了群里还会收到补漏报警。要根治，就找到并停掉那个程序，或者给机器人换一个专用应用。日志里的「事件晚到，这条已由轮询处理」说明事件只是推送慢，不是被分走，不算在报警里。
- **经验库表格的记录文件**：机器人自己建的经验库表格记在 `data/knowledge/bitable.json`，里面是表格在哪、共享给了哪些群和人。换服务器或重新部署时，连同 `data/` 整个拷过去。这个文件丢了，机器人就不知道以前共享给了谁，以后移出名单的群和人也撤不掉；而这张表设成了只有机器人能管协作者，别人在飞书里也改不了。真丢了的话，不要把旧表填进 `KNOWLEDGE_BITABLE` 接着用：让机器人新建一张（`KNOWLEDGE_BITABLE` 留空），把旧表里的经验复制过去。旧表还共享着以前的群和人，机器人也管不了它了。
- **群记忆存在哪、怎么恢复或清空**：每个群一个文件 `data/memory/<chat_id>.json`（`DATA_DIR` 可改位置），只有运行程序的用户能读写。每天的备份在 `data/backup/memory/<日期>/`，和记忆在同一块盘上，防的是误删、写坏，不防整块盘坏掉。恢复一个群：先停服务，把备份里的 `<chat_id>.json` 复制回 `data/memory/`，再启动（程序运行时会缓存记忆，不停服务直接复制会被覆盖）。清空一个群的记忆就停服务、删掉它的文件、再启动。记忆的增删改会记在日志里（`群记忆 chat=… 新增 #3 操作人=…`），只记编号和操作人，不记内容。
- **日志里出现「群记忆文件损坏」**：程序把坏文件改名成 `…json.corrupt-时间戳` 留着，这个群从空记忆重新开始，可以手动从坏文件里把内容找回来。

## 当前限制（后续阶段解决）

- 群记忆只在有人 @ 机器人时写入，机器人不会自己去翻群里没 @ 它的聊天记录。
- 记忆超过提示词的字数上限（约 8000 字）时只列最近更新的，更早的靠关键词查找，还没有向量检索。每个群最多 300 条。
- 群里任何人都能让机器人记住或忘掉东西，权限控制在阶段 5 做。
- 飞书文档只支持新版文档（docx）和知识库里的新版文档；旧版文档、电子表格、多维表格还读不了，写入时图片会变成链接。
- 机器人能读写所有给它开过权限的文档，群里任何人都能让它读其中任何一篇；配了 `WRITE_ALLOWED_USERS` 后只有名单里的人能让它改。按群限制范围在阶段 5 做。
- 联网搜索只支持百炼；换成别家模型服务时搜索自动关掉。
- 代码仓库支持 GitLab 和 GitHub；机器人不运行代码和测试（要隔离的运行环境，阶段 5 做），合并请求要人审查后合并。没配 `WRITE_ALLOWED_USERS` 时，群里任何人都能让它改 `CODE_REPOS` 里的仓库并开合并请求。
- 团队经验库所有白名单群共用，按群控制能看哪些经验在阶段 5 做。确认卡片的草稿存在内存里，机器人重启后旧卡片点了提示失效，要重新让它起草。直接在多维表格里改的排查经验不会同步到 aiops 经验库，要改的话让机器人起草新的一条替换旧的。
- MCP 只支持 HTTP（Streamable HTTP）服务，还不能接 stdio 类的本地 MCP 服务。模型只能用 aiops 的只读工具；存经验、归档经验只能经确认卡片，由写权限名单里的人点确认。白名单里的群都能用 aiops，按群限制能用哪些 MCP 服务和工具在阶段 5 做，加第二个群之前要先有这一项。
- 单聊暂不响应，只处理群里 @ 机器人的消息。
- 去重记录、进行中的任务和本地记下的问答都在内存里，重启后清空（群记忆在磁盘上，不受影响）；重启时进行中的任务会被标成「已停止」。多开几个实例也不会重复回答，飞书只把每个事件推给其中一个连接。
- 回答不是流式输出，模型想完才一次发出。
- 没有定时任务。
