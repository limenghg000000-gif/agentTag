# AgentTag

仿照 Claude Tag 做的飞书版团队 AI 助手：机器人作为成员加入飞书群，群里任何人 @ 它即可提问或派活，它在那条消息的话题里回复。

当前是阶段 4（定时任务），已接上飞书云文档、联网搜索、代码仓库、通过 MCP 接入的运维系统 aiops，能按时间提醒、定期去查去汇总：

- **飞书云文档**：群里贴一个飞书文档链接（新版文档或知识库页面），@ 机器人让它看、总结、按文档回答问题；也可以让它把讨论整理成一篇新文档，或者改已有的文档（追加、在某段前后插入、替换、删除）。新建的文档自动共享给本群（可编辑）和发起人（可管理），回答里附上链接。机器人要先有这篇文档的权限，见下面「飞书云文档的权限」。
- **群记忆**：机器人给每个群记下长期有用的信息（项目背景、做过的决定、团队约定、成员分工和偏好），群里任何话题、隔多少天再 @ 它都能用上。可以直接说「@机器人 记住：……」「你记得什么」「忘掉 #3」；对话里出现决定、约定这类信息时它也会主动记，并在回答末尾说一句「已记住：……」。@ 它给它定以后的规矩（「线上报错必须 @ 你再直接帮忙查」「以后告警别管」「这类消息不用回」），没说「记住」也记成约定，这次只记、不照着去查（这句话里没说「现在」「这次」「顺便」查、「查一下」「看下」，也不是在问的，程序只给记群记忆的工具、不查经验库）；程序按这句话本身认（说到要不要 @ 它、一句话开头的「以后」「从现在起」、「你只回」「别管」「不用回」这类），群里刚才的聊天带着时也认，定时任务的内容不算。
- **补漏轮询**：同一个飞书应用如果还有别的程序连着长连接，飞书会把一部分 @ 推给那个程序，机器人就收不到。机器人每 10 秒读一次白名单群和它参与过的话题里的新消息，把没从事件收到的 @ 补上处理（晚几秒回复），日志里记一行「补漏：事件没送到，由轮询补上」。30 分钟内补上 2 条以上（事件过了 1 分钟还没到），机器人会在群里发一条补漏报警，1 小时内不重复。
- **群记忆每日备份**：每天把所有群的记忆复制一份到 `data/backup/memory/<日期>/`，保留最近 14 天。
- **话题里接着聊**：在机器人回复的话题里追问，它会带着话题里之前的消息回答。追问不用再 @ 它（`FOLLOW_THREADS`，默认开）：机器人回答过的话题里（不限时间，隔几个小时、隔几天回来接着问都算；最多记 2000 个话题，超出时先忘最久没 @ 过它的），没 @ 它的消息先让模型（关着思考）看一眼话题最近几条和群记忆，判断是不是对它说的（接着追问、让它继续做、纠正它），是才回；群成员之间说话、表个态（好的、收到）不回，@ 了别人的、机器人和应用发的不看，判断出错时也不回。日志里每条记一行「跟聊：没 @ 的话题消息是/不是对机器人说的」。没 @ 的话只给读的工具：话题里谁都能写字，要新建或修改文档、改代码、开合并请求得 @ 它直接说；群记忆也只在这句话本身让它记住、忘掉时才记、改、删。话题里说「只在 @ 我时回」「别插话」，这个话题之后只在 @ 它时回。跟着哪些话题、哪些话题说过「只在 @ 我时回」记在 `data/follow.json`，部署重启后接着跟、照样不跟。群主界面里没 @ 它的消息不回，除非这个群开了下面的主动接话。
- **带上群里刚才的聊天**（`CHAT_CONTEXT`，默认开）：在群主界面直接 @ 机器人时，把这条 @ 之前半小时内的群聊（最多 20 条、6000 字，不含机器人自己发的）一起给模型，标明不是对它说的，「看下上面那个报错」「刚才张三说的那个」接得上；里面的截图也会识别（一次最多 4 张）。这段不拿去查经验库。群聊里谁都能写字，所以群聊和改文档、改代码的工具不同时给：提问本身直接说了要改哪个文档或代码（「追加到周报文档里」「修一下这段代码」「修改 src/bot.ts」「update README.md」「切到 develop 分支」「开个 MR」这类说法）的，给改的工具、不带群聊（要写进去的内容请直接写在 @ 的话里）；没这么说的，带上群聊、只给读的工具，也不能切代码分支；群记忆只在这句话本身让它记住、忘掉，或者在给它定以后的规矩时才记、改、删（群聊里埋的「忘掉 #3」不算）。这样有人在群里埋一句话，也借不到写权限名单里的人的 @ 去改文档或代码。
- **主动接话**（`PROACTIVE_CHAT_IDS`，默认没有群，照 Claude Tag 2026 年 8 月的做法）：打开了的群里，群主界面和机器人没跟着的话题里没 @ 机器人的消息，让模型（关着思考）连同群记忆和刚才的 10 条群聊（话题里的看话题最近 8 条）看一眼，大多数不接。要接的有三种：答案就在群记忆或刚才的聊天里，直接回一句（会说出处）；群记忆里定过规矩说这类事不用 @ 也要它处理（比如「线上报错不用 @ 你也直接帮忙查」，@ 它说一句就能定），像被 @ 了一样去查、去答（只给读的工具）；「做」这个选择只在群记忆里有这样的规矩时才给（程序看群记忆里有没有一条说「不用 @」「没 @ 也」「直接帮忙查」「主动帮忙看」这类、同一条里又没说要先 @ 它的），规矩说要 @ 它才处理的（「线上报错必须 @ 你再查」），提示词让它没 @ 就不接，不查也不问；有人提了它能帮的事、还没人接，只问一句要不要它来。要接的先打开思考、同样的材料再问一遍，还要接才接，回的是想过以后的那句；回之前核对出处：说到的「群记忆 #几」要真有，两位以上的数字、版本号、时间要在群记忆、聊天或这条消息里原样出现过，对不上的不接（日志「主动接话：打开思考再想一遍，不接了」「要说的话出处对不上」）。像提问、像报错的消息（问号、吗、怎么、咋、排查、报错、失败、超时、打满、告警、卡住、变慢、5xx、code=、exception、OOM、down 这类），看一眼之前先查团队经验库和 aiops 经验库（和回答前自动查的同一个，查这条加上之前最近 3 条群成员说的，最多多等 10 秒；`KNOWLEDGE=off` 时不查），查到的一起给模型判断：报错码、服务名对得上的说「之前遇到过（经验 K3，日期）」、照抄原因和处理办法并问要不要查这次是不是同一个原因，半年以前的提醒可能过时；只是像的只问一句「可能和经验 K3 有关」；查到了也不一定开口。别的消息第一眼想开口的，再想一遍之前再查一次（跟聊交过来的也是）。说到的「经验 K3」「aiops 经验 #N」要是这次查到的，对不上不接（日志「主动接话：像提问或报错，看一眼前查了经验库」「要开口，再想一遍前查了经验库」）。回之后这个话题交给跟聊，接着说不用 @。和 Claude Tag 一样不限每小时接几次（`PROACTIVE_MAX_PER_HOUR` 填了才限，回一句和去做都算），每个群每小时最多判断 120 条；也和 Claude Tag 一样，机器人上次在群里说话以后群里发了 200 条它都没说过话，或者 10 天没人 @ 它、它也没在群里说话，这个群先不看了，不主动接话（日志「主动接话：…这个群先不看了」，启动日志里也列出来），有人 @ 它、它回了以后接着看（它回答过的话题照样跟）；每次没被 @ 时开口有没有人理也记下来（1 小时内在它开的话题里回了、@ 了它、引用回复它、点了表情算理了，点「踩」不算；点表情要在飞书开发者后台订阅「消息被 reaction」事件才收得到，没订阅就只看回复和 @），判断时把最近 10 次有几次没人理写进提示词，没人理的多时只接答案确定、有人在等的，不问要不要帮忙（日志里「最近没被 @ 时开口有人理=M/N」），这些和开关一起记在 `data/proactive.json`，重启后接着算；太短的、只是表态的、@ 了别人的、机器人和应用发的不看。每个群每天第一次主动回时，后面带一句怎么关。群里 @ 它说「别主动插话」就停（重启后也记着），「可以主动说话」再打开；没打开的群里说这些，它会回一句这个群没开。日志里每条记一行「主动接话：接一句/照群里的规矩，像被 @ 一样去做/不接」。打开了的群里，跟聊在跟的话题里判断时多两个选择：不是对它说的、但答案就在群记忆里、一两句说得清，在话题里接一句（写明群记忆第几条）；是群记忆里定过规矩要它处理的那类事，去做（机器人正在做这个话题里的事、群记忆是空的时不给这两个选择；群记忆里没有不用 @ 也要它去做的规矩时不给「做」）。同样先再想一遍、核对出处，和群主界面的主动接话共用每小时的次数；照规矩去做的只给读的工具，这句话本身说了记住、忘掉也不能记、改、删群记忆和起草经验；话题里说「只在 @ 我时回」后也不再接。日志「跟聊：…答案在群记忆里，看要不要接一句」「主动接话：话题里接一句」。
- **定时任务**（`SCHEDULED_TASKS`，默认开）：群里 @ 机器人「每周一早上 9 点汇总上周群里的进展」「工作日每天 10 点查一下昨晚 gateway-api 有没有报错」「明天下午 3 点提醒我看发版」，模型用 `schedule_create` 建一个任务（编号 T1、T2…，周期的写 5 段 cron，一次性的写时间，都按北京时间），「这个群有哪些定时任务」用 `schedule_list` 看，「暂停/恢复/取消 T3」用 `schedule_change`（暂停谁都能，恢复、取消见下面「权限」）。这三个工具只在这句话说到定时、提醒、以后某个时间（「每周」「工作日」「明天」「3 点」「T3」这类）时给；主动接话、整理之前内容的、定时任务自己跑的不给，点按钮问的、没 @ 的跟聊只给 `schedule_list`；带着群里刚才的聊天时不给 `schedule_change`（群聊里埋的「取消 T3」借不到任务主人、管理员的 @），这句话本身说了暂停、恢复、取消的不带群聊。任务存在 `data/schedules.json`（`DATA_DIR` 下），重启后接着跑，读坏了先复制一份成 `…json.bad-时间戳` 留着、从空的开始（日志「定时任务：… 读不出来」）。
  - 到点：程序每 30 秒看一次，到点的在原来的群里发一条「⏰ 定时任务 T3 · 每周一 09:00 · 谁建的」加上任务内容，再像有人在这条消息下 @ 机器人一样去做，回答在这条消息的话题里（之后话题里接着问照常跟聊）。纯提醒（`remind`）只发「⏰ 提醒」，不调模型。一次性的和纯提醒的会 @ 建的人，周期任务正常跑完不 @ 人。同时最多跑 2 个，其余排着。
  - @ 人：只 @ 建任务的人，@ 由程序拼（`mentions`），模型写的字里的尖括号都换成全角，@ 不了别人和所有人。没跑成、连着失败自动暂停、被别人暂停或取消、一次性的错过了，在群里 @ 建的人。建的人说了「有异常 @ 我」的（`alert_creator`），到点多一个工具 `schedule_alert_creator`，模型查到异常时调，回答发完后在结果话题里 @ 建的人。
  - 周报文档（`append_doc`）：建的人要每次追加到同一篇时，在这句话里自己贴文档链接；工具按文档编号核对链接在发起人这句话里（工具上下文的 `question`），而且这次能改（`writable`）才记成任务的 `appendDoc`。到点只给这种任务 `feishu_doc_edit`，只认 `append` 到这一篇，读过群聊以后也能追加；插入、替换、删除、别的文档一律拒。没绑文档的任务到点不能改已有文档，可以新建。
  - 权限：任务记在建的人名下，到点按他的权限跑，不会比建的时候大：建的那次只给了读的工具（不在 `WRITE_ALLOWED_USERS` 里、带着群聊、没 @ 的跟聊），或者建的人这句话本身没说要改哪篇文档（任务内容是模型写的，不算数），就记成只读；到点时建的人不在写权限名单里了也只读；任务内容本身没说要写文档、也没绑文档的只给读的工具。到点跑的不带群聊，不给改代码、开合并请求、合并、切分支的工具，不给定时任务的工具，群记忆和经验草稿只在任务内容本身说到时才能改。暂停谁都能做（只会让机器人少做事）；恢复、取消只有建的人和写权限名单里的人能做（没配名单时所有人）。
  - 上限：每个群 20 个、每人 10 个（暂停的也算）；同一个任务两次之间至少 60 分钟；一个群所有任务（不算纯提醒）加起来每天最多跑 48 次；任务内容最多 1000 字；一次性的最多排到一年后。
  - 出错和停机：每次没跑成都 @ 建的人，连着 3 次没跑成（出错）自动暂停，@ 它「恢复定时任务 T3」再开；点了停止、重启打断的不算失败。到点时机器人没在跑，重启后晚 2 小时以内照样补跑（消息里写明晚了多久），再晚的周期任务等下一次、一次性的在群里 @ 建的人说错过了。群从 `FEISHU_ALLOWED_CHAT_IDS` 里去掉后，那个群的任务到点跳过。每次到点先把下次时间写进文件、等写完再发消息，重启不会把同一次跑两遍；写不进文件（磁盘满、没权限）时这次不跑、记成出错（日志「下一次的时间没写进文件，这次不跑」）。
- **读本群的聊天记录**（`chat_history`）：「总结一下这周群里聊了什么」「汇总上周群里的进展」时，模型按时间段（北京时间，最多 8 天）读本群的聊天记录：群主界面最多 200 条，最近 20 个话题里的回复一起列出，机器人发的卡片换成它当时的回答，每条最多 300 字、一共最多 2 万字，太长时去掉最早的。用已有的「获取群组中所有消息」权限。群聊里谁都能写字，所以这次读过群聊以后（和它同一轮一起调的、从这个话题之前查到的结果里取回读过的群聊也算），再调改已有文档、改代码、合并这类写的工具会被拒（新建飞书文档可以），不能切代码分支、不能暂停或取消定时任务，这时建的定时任务记成只读（免得群里埋的话借定时任务挪到以后去做），群记忆只在这句话本身让它记住、忘掉时才能改。
- **联网搜索**：要查新闻、版本、价格这类最新信息时，机器人用百炼模型自带的联网搜索查，回答里附上来源链接。每次搜索会多调一次百炼模型，另按百炼的联网搜索计费。
- **代码仓库**（公司自建 GitLab，也支持 GitHub）：配好允许的仓库后，可以在群里问代码的问题（机器人拉下代码来搜、来读，回答带分支、文件和行号；模型没读代码就说仓库里的内容时，程序会把这版回答打回去，让它先查再答）。默认看仓库的默认分支，在群里说「看 aiops 分支」它就切过去，这个话题后面都用这个分支；默认分支上找不到、或者不知道在哪个分支时，它会在最近有提交的几个分支上一起搜。能查提交历史（按提交说明里的词、改过的文件、起始日期），用来确认问题是不是已经修过、修复合进了哪个分支；读代码只要了一小段时，会给出所在的整个函数，免得只看报错附近几行。aiops 按线上版本读代码时给的永久链接也算查证过的代码位置。也可以让它改代码、开合并请求。它从线上分支拉自己新建的分支（`agenttag/…` 或群里给的名字）改，不会推到已有的分支；线上分支按项目认：读默认分支上的 `.gitlab-ci.yml`，按分支部署的分支里受保护的那个是线上分支（默认分支在里面就用默认分支，`CODE_REPOS` 里写了 `@分支` 就用写的），其余按分支部署的（uat、test 这类）是测试环境分支，只看不改。说「合到 uat」时从同一个分支再开一个到 uat 的合并请求（推之前先把改动放到 uat 上试，有冲突、编不过不推），测完再开到线上分支；在同一个话题里接着让它改，推到同一个分支，几个合并请求一起更新。它不在服务器上运行代码和测试。
- **线上排查（aiops，通过 MCP 接入）**：群里 @ 机器人「xx 服务最近一小时报什么错」「诊断一下 xx 服务」「现在有哪些告警」「xx 的 Pod 为什么重启」「接着查案例 #N」，它调团队的 aiops 系统查 K8s、Loki 日志、Prometheus 指标和 Tempo 链路，按查到的证据回答。排查服务问题时先用 aiops 的一键诊断，再补查几次；一次任务里 aiops 工具最多调 10 次，同样的参数不重复调。不说命名空间时由 aiops 按服务名自己定位，同名服务在几个命名空间时机器人会先问查哪个。配了代码仓库时，查过线上以后回答把问题推到服务之外（「不是服务故障」「建议用户重新分享」「属于平台限制」）会被程序打回一次，让模型先拿失败请求的特征搜代码、沿主流程核对，结论分开写当时为什么失败、现在的代码处不处理、线上部署了没有。模型只能用 20 个只读工具。每次调用都记审计日志（谁问的、哪个群、哪个工具、参数摘要、结果大小、用时），因为 aiops 那边用的是共享令牌，不知道是谁让机器人查的。
- **团队经验库（飞书多维表格）**：所有群共用，存有人确认过的结论，分排查经验、应答卡、数据口径、需求结论几类，编号写成 K1、K2。表格里删掉的行的编号不再发给新的经验（发过的最大编号记在 `data/knowledge/issued.json`），旧消息里提到的编号不会指到别的经验上。
  - 提问前，程序先拿问题去经验库查一次；一个话题查成过一次（不管查没查到）以后，追问不再自动查，追问里有新报错、新问题时模型自己查。没查成的（超时、出错、只查成一边）下次追问补查；追问里明说「查经验库」的照样先查。查成过哪些话题记在内存里，重启后忘了就再查一次（关键词加百炼向量模型按意思查；接了 aiops 时 aiops 自带的经验库也查），查到相近的就附给模型。回答里写「参考经验 K3」，但还是要按这次查到的证据下结论。这一步最多等 8 秒：哪边没查完就不等它，向量没算完就只按关键词，不耽误回答。表格读不出来（飞书接口出错、超时）时先用上次读到的，1 分钟内不再重读，不会每个问题都等到超时；刚存过、归档过经验时没有能用的旧表格，这 1 分钟里不查团队经验库。保存、归档、核对卡片照样要读到表格现在的样子。
  - 只有在群里明确说「沉淀到经验库」这类话时，机器人才起草一条，发一张确认卡片。写权限名单（`WRITE_ALLOWED_USERS`）里的人点「保存」，程序才按卡片上的内容写进去；别人点无效，24 小时没人点就失效。没配写权限名单时经验库只能查、不能存和归档：经验库所有群共用，存进去的会写进别的群回答前的提示词，谁都能存的话一个群就能影响别的群的回答。
  - 经验库里有很像的经验时，卡片上会提示。改错就起草新的一条替换旧的；删就是归档。都走确认卡片。新的一条在表格的「取代的经验」列里记下替换的是哪条（「取代的经验的草稿编号」列记它的草稿编号，旧的那一行改了编号也认得出）；旧的那条还没归档时（比如归档那步没做成），别的卡片不能再替换它，免得两条新的同时有效。
  - 群记忆和经验库说法对不上时，回答按日期新的那边说，并提一句两边不一致；机器人再发一张冲突卡片，每处列出两边现在的说法、哪边更新、选了以后各改成什么，下面一个下拉框选「以群记忆为准」「以经验库为准」或「先不动」（默认选更新的那边）。群里谁都能改选择；点「按选择同步」后输的那边改成和赢的一样：以经验库为准就改掉（或删掉）那条群记忆，以群记忆为准就按卡片上的新结论存一条新经验、归档旧的（和点「保存」一样，排查经验同步 aiops）。卡片发出后两边任何一边改过，这一处都不动；有一处没做成时卡片写「没全同步成」，有选「先不动」的写「已按选择同步，有 N 处先不动」。只改群记忆的群里谁都能点；要改经验库的只有写权限名单里的人能点。新经验没存成、后面的步骤没做完时另发一张确认卡片接着做。群里说「查一下群记忆和经验库有没有冲突」时，机器人把群记忆逐条和经验库对一遍，对不上的列进同一张卡片（一张最多 8 处）。
  - 排查经验保存时同时写一份到 aiops 经验库，告警自动排查和 Open WebUI 也能用上；归档时两边一起归档。aiops 连上了却少了同步、归档要用的工具（save_lesson、archive_lesson，再试时要用的 search_knowledge、get_knowledge；版本旧、没配 MySQL，或者 MCP_AIOPS_TOOLS 里没开这两个读的）时只存团队经验库，卡片上也不说会同步；卡片发出后 aiops 才少了这些工具的，算没做完，补上工具后点「再试一次」接着同步。
  - 草稿或归档原因里有令牌、密码这类密钥，或者手机号、身份证号时，程序不让发卡片（用户姓名这类认不出格式的靠提示词）；名字里像是有密钥的发起人、确认人只记 open_id。有人直接在表格里写进了密钥、手机号、身份证号，或者清空了标题或结论的那一行，检索时跳过、不给模型看，日志里记一条让人去表格里改；aiops 里别处存的经验有这些的也一样不给模型看、不列在卡片上。卡片上草稿、表格、aiops 来的内容都转义了尖括号，里面的 `<at id=all></at>` 不会 @所有人。卡片发出后有人在表格里改了要归档、要取代的那一条，点确认时卡片作废。
  - 第一次保存时机器人自己建一张多维表格「AgentTag 经验库」：白名单群只读，写权限名单里的人可以直接在表格里看、筛选和修改（可编辑）。只有机器人能加、移除协作者，链接分享和分享到组织外都关掉，所以名单外的人打不开，名单里的人也没法再共享给别人；这一步没设好之前（比如还没开权限）先不共享给任何人。表格链接在保存结果里，建表时日志里也记一行。共享跟着白名单群和写权限名单走：启动时和每次保存时补上没共享成的（比如还没开权限）、撤掉移出名单的，撤不掉的每 10 分钟再试一次；别人在飞书里手动加的协作者不动。
  - 点「保存」后结果没传回来、卡片提示失败再点一次时，不会存成两条（每张卡片有一个草稿编号，写在表格的「草稿编号」列里）。
  - 存进经验库以后，同步 aiops、记 aiops 编号、归档被取代的旧经验这几步有没成功的，卡片变成「已存进经验库，还有没做成的」，列出没做成的，可以点「再试一次」补上：做完的不会再做一遍（表格那边按草稿编号或编号找上次存进去的那一行，两列都被改了就说找不到、不再存；aiops 那边先按出处找有没有已经存进去的那条）。同步到 aiops 的只有写权限名单里的人确认过的内容（aiops 的经验告警自动排查会引用）：表格里这一行和确认的不一样时（再试之前在表格里改过，或者存进 aiops 后重新读表格发现这期间改过），不按改过的同步，已经存进去的那条归档，卡片上列出表格里现在的内容，名单里的人核对后点「再试一次」才按它同步；点的是没列这些内容的旧卡片不算。改进去的密钥不会同步过去；再试之前在表格里归档了它或者改成别的类别，就不再同步。取代旧经验时，新的没进 aiops 就不归档 aiops 里旧的那条。归档 aiops 里同步的那条之前，先核对它排查过程末尾注明的出处是不是表格里这一条：有人在表格里把 aiops 编号改成了别的经验的，不归档，卡片上说明，改正后再试一次。写权限名单里的人点「不用了」或者超过 24 小时就不再试（发起人不在名单里时只能取消还没确认的卡片）。机器人重启后这张卡片就不能再试了，没做成的要手动处理。
- **多步工具调用**：模型可以自己决定调用工具、分几步完成任务。目前有联网搜索、读取网页、飞书云文档、代码仓库、群记忆，以及通过 MCP 接入的工具（aiops）。
- **进度卡片**：每个任务先在话题里发一张卡片，实时显示正在执行的步骤，结束后收成一行「已完成 · N 步 · 用时」。开着思考时，卡片上还会显示模型每轮的思考（像 Open WebUI 的「思考过程」），结束后和步骤一起折叠，点开能看。
- **卡片即回答**（`STREAM_CARD`，默认开）：思考和回答边生成边写进这张卡片（打字机效果），回答就在卡片里，不再另外发。回答没通过检查时，卡片里那一版换成「正在重做」，重做的回答写出来以后替换它。更新卡片不发通知，所以从提问到写完超过 1 分钟（排队也算）时，在话题里补一句「处理完了，结果在上面的卡片里。」提醒提问人。回答太长时卡片里只放开头，全文另外发；建不了流式卡片时退回老办法：卡片只显示进度，回答另外发。
- **深度思考**：为了回答快，默认不开模型的思考模式。遇到难题（排查复杂问题、设计方案、改代码前的分析），在问题里写「深度思考」「仔细想想」或「认真分析」，这一次会打开思考，慢一些但想得更周全；最多想 4000 token（大约两分钟），超过就直接回答。
- **中途停止**：点卡片上的「停止」按钮，或在话题里 @ 机器人说「停止」（机器人在跟的话题里不 @ 也行）。
- **不重复处理「同时发送到群」**：在话题里 @ 机器人时勾了「同时发送到群」，群里会多出一条一样的消息。同一个人 10 秒内发的同一句话只处理一次（话题里那条优先），写文档这类操作不会做两遍，日志里记一行「跳过重复的提问」。
- **知道自己叫什么**：机器人在飞书里的名字（比如「飞书 CLI」）会写进提示词。
- **更新通知**：发版部署、重启后，机器人把产品更新说明 [RELEASE_NOTES.md](RELEASE_NOTES.md) 里各群还没收到过的版本发到群里（一张「AgentTag 更新了」的卡片）。发到哪些群看 `.env`：配了 `ANNOUNCE_CHAT_IDS` 就只发这几个群，没配就发 `FEISHU_ALLOWED_CHAT_IDS` 里的所有群，启动日志里会列出来。每个群收到哪一版记在 `data/announce/state.json`，重启不会重发；新加的群第一次只收到最新的一版。卡片上每个版本先写「本次更新了什么」（产品版的大白话），配了文档链接的新功能下面跟着它的文档按钮，下面折叠一个「技术说明」，放技术版更新日志 [CHANGELOG.md](CHANGELOG.md) 里同一版本的内容，点开才看得到；最下面是「产品功能说明」「文档中心」两个按钮。
- **问「你能做什么」**：只问「你能做什么」「我想看看所有功能」这类话时，机器人直接回一张功能卡片：内容是产品功能清单 `FEATURES.md`（和产品功能说明的「一览」一致，只列机器人配了工具的那几项），每项点开看怎么用、怎么问，带「试一试」的问法能直接点（只查不改），最下面是产品功能说明的按钮（`ANNOUNCE_LINK`）。问法不一样的交给模型，也按这份清单说；最近更新了什么按 `RELEASE_NOTES.md` 最新一版回答。

长连接模式只需要能访问公网，不需要公网地址，内网服务器或本地电脑都能跑。

模型通过 OpenAI 兼容接口调用，默认接阿里云百炼。接口地址、Key、模型 ID 都从环境变量读，换千问、Kimi、GLM 等模型不用改代码。

## 工作方式

```
飞书群 @机器人
  → 飞书长连接（WebSocket）推送 im.message.receive_v1
  → 飞书 SDK Channel：识别 @、按消息 id 去重、丢弃过期重推，事件处理立即返回（飞书要求 3 秒内确认）
  → bot.ts：只处理群白名单里的群，取出问题（去掉 @机器人，其他 @ 换成名字）；「停止」指令直接停任务
  → tasks.ts：同一话题里的任务排队依次执行，不同话题并行
  → 在话题里发进度卡片（带停止按钮）
  → history.ts：读取话题里之前的消息作为上下文
  → memory.ts：读出这个群的记忆写进系统提示词，并给这次任务配上只能读写这个群记忆的工具（tools/memory.ts）
  → 给这次任务配上飞书云文档工具（tools/docs.ts），新建的文档共享给当前群和发起人
  → mcp.ts：配上 MCP 服务的工具（如 aiops），调用次数按任务算；服务端的使用说明写进系统提示词
  → tools/knowledge.ts：先在团队经验库（和 aiops 经验库）里查相近的经验写进系统提示词，再配上查经验、起草经验的工具
  → agent.ts：工具循环。问模型 → 模型要调工具就执行（tools/）并把结果交回 → 直到给出回答；每一步更新进度卡片
  → 卡片改成「已完成」，回答以富文本（Markdown）发到话题里，过长时拆成多条

点卡片上的「停止」→ 飞书长连接推送卡片回调 card.action.trigger → 中止对应任务（正在进行的模型请求和工具调用一并取消）
点经验库确认卡片上的「保存」「归档」→ 同一个卡片回调 → 写权限名单里的人点的才执行，按卡片上的内容写进多维表格（排查经验再同步到 aiops）
点冲突卡片上的下拉框、「按选择同步」→ 同一个卡片回调（tools/conflicts.ts）→ 记下每处的选择；同步时改群记忆，要改经验库的写权限名单里的人点的才执行
```

## 目录

| 文件 | 作用 |
| --- | --- |
| `src/index.ts` | 入口：读配置、建立飞书长连接、注册消息和卡片按钮处理、优雅退出 |
| `src/config.ts` | 从环境变量读取并校验配置 |

| `prompts/mcp/` | MCP 服务在飞书群里的使用说明（`aiops.md`），开了它的工具时写进系统提示词。改完不用重启，每 10 分钟重新读一次 |

| `src/docs.ts` | 飞书云文档：解析文档和知识库链接、调文档接口、按块插入/替换/删除、新建后共享给群，把接口错误翻译成能转告的话 |

| `src/history.ts` | 读取话题上下文：优先从飞书读整个话题，读不到时用本地记下的问答；群里直接 @ 时带上之前半小时内的群聊 |

## 第一步：在飞书开放平台创建应用

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建「企业自建应用」。
2. **添加应用能力** → 添加「机器人」。
3. **权限管理** → 开通以下权限：
   - `im:message.group_at_msg:readonly`（接收群聊中 @ 机器人消息事件）
   - `im:message:send_as_bot`（以应用的身份发消息，也用来更新进度卡片）
   - `im:message.group_msg`（获取群组中所有消息，敏感权限，需要管理员审核）：用来读取话题里之前的消息。不开也能用，但追问时机器人只记得之前 @ 它的问题和它的回答，看不到话题里其他人没 @ 它的发言，而且重启后就忘了。开了以后机器人会收到所在群的所有消息事件，程序只处理 @ 它的、它回答过的话题里的追问（见「话题里接着聊」）和打开了主动接话的群里的消息，其余直接丢弃，白名单外的群一律不看。群里直接 @ 时带上刚才的群聊（`CHAT_CONTEXT`）也要这个权限，没开时日志里会有「读取群里刚才的聊天失败」，只看提问本身。
   - `im:resource`（获取与上传图片或文件资源）：下载提问里的截图交给模型看。不开时机器人看不到图片，会请对方把图片里的文字贴出来。
   - `cardkit:card:write`（创建与更新卡片）：卡片即回答要用。不开时自动退回老办法（卡片只显示进度，回答另外发），日志里有「建流式卡片失败」。
4. **凭证与基础信息** → 记下 App ID 和 App Secret，填进 `.env`（见第三步）。
5. **版本管理与发布** → 创建版本并发布，让机器人和权限生效。
6. 按第三步把程序跑起来，保持运行。
7. **事件与回调** → 事件配置 → 订阅方式选「使用长连接接收事件」并保存（程序没在运行时保存会失败）→ 添加事件「接收消息」`im.message.receive_v1`。
8. 可选，用飞书云文档和团队经验库时开：**权限管理** 里再开通下面这些。可以用「批量导入」粘贴 `{"scopes":{"tenant":["docx:document","docx:document.block:convert","wiki:wiki:readonly","docs:permission.member:create","docs:permission.member:update","docs:permission.member:delete","docs:permission.setting:write_only","drive:drive.metadata:readonly","bitable:app","contact:user.base:readonly"],"user":[]}}`，个别权限名在你的后台搜不到时去掉它，缺什么机器人用到时会报出来。
   - `docx:document`（查看、编辑新版文档）：读文档、新建文档、改文档
   - `docx:document.block:convert`（把 Markdown 转成文档块）：写入内容
   - `wiki:wiki:readonly`（查看知识库）：读知识库链接背后的文档
   - `docs:permission.member:create`（添加文档协作者）：新建的文档共享给群和发起人，不开的话新建的文档谁都打不开
   - `docs:permission.member:update`（更新协作者权限）、`docs:permission.member:delete`（移除协作者）：团队经验库的多维表格跟着白名单群和写权限名单走，名单里去掉的群或人要撤掉权限，权限变了要改。不开的话撤不掉，被移出写权限名单的人还能直接改表格，日志里会有警告写明缺哪个权限
   - `docs:permission.setting:write_only`（更新云文档权限设置）：把团队经验库的多维表格设成只有机器人能加、移除协作者，关掉链接分享。不开的话机器人不把表格共享给任何人（群里打不开表格，检索和保存照常），免得拿到权限的人再共享出去，日志里有警告；开了以后下次启动或保存时自动共享
   - `drive:drive.metadata:readonly`（查看文件元数据）：拿新建文档的链接。不开也行，机器人会用群里贴过的文档链接的域名拼
   - `bitable:app`（查看、评论、编辑和管理多维表格）：团队经验库。不开时回答前的检索照常（还没有表），保存经验时卡片上会提示缺这个权限。建表后共享给群、撤掉或改权限要用上面三个 `docs:permission.member:*`，限制谁能共享要用 `docs:permission.setting:write_only`
   - `contact:user.base:readonly`（获取用户基本信息）：飞书点卡片按钮时只给点的人的 open_id、不给名字。经验库确认卡片、冲突卡片上写「谁点了」、表格记「确认人」时，机器人先在卡片所在话题里找这个人说过的话，没找到再查通讯录拿名字。要查得到，这个人还得在权限管理里「通讯录权限范围」之内。不开时只在话题里找，找不到写「有人」「写权限名单里的同事」
9. **事件与回调** → 回调配置 → 订阅方式选「使用长连接接收回调」并保存 → 添加回调「卡片回传交互」`card.action.trigger`。不配的话点进度卡片上的「停止」会报错，但在话题里 @ 机器人说「停止」照样能停。
10. 再创建一个版本并发布，让事件和回调订阅生效。以后改权限、事件或回调都需要重新发布。
11. 在飞书里建一个测试群 → 群设置 → 群机器人 → 添加这个机器人。

## 第二步：开通阿里云百炼 API Key

1. 登录 [阿里云百炼控制台](https://bailian.console.aliyun.com)，开通服务。
2. 创建 API Key，填进 `.env` 的 `MODEL_API_KEY`。要用**按量计费的普通 API Key**，不要用 Coding Plan 的 Key，它的条款不允许用作应用后端。
3. 可选：百炼为北京地域推出了业务空间专属域名，建议把 `MODEL_BASE_URL` 设为 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`（WorkspaceId 在控制台查看）。不设时用默认的 `https://dashscope.aliyuncs.com/compatible-mode/v1`。

## 第三步：运行

需要 Node.js 22 或更高版本。

```bash
npm install
cp .env.example .env   # 填入 FEISHU_APP_ID、FEISHU_APP_SECRET、MODEL_API_KEY
npm run dev            # 开发模式，改代码自动重启
```

看到 `飞书长连接已建立，机器人「…」` 就说明连上了。完成第一步剩下的事件订阅和发布后：

1. 在测试群里 @ 机器人随便说一句。机器人默认不响应任何群，终端会打出 `忽略白名单外的群 chat=oc_xxx`。
2. 把这个 `oc_xxx` 填进 `.env` 的 `FEISHU_ALLOWED_CHAT_IDS`，重启程序。
3. 再 @ 机器人问个问题：话题里先出现一张进度卡片，回答边生成边写进这张卡片（没开 `cardkit:card:write` 时回答另外发在卡片下面）。
4. 在这个话题里直接追问（不用 @），它会接着前面的内容回答；在话题里跟别人说「好的收到」，它不会回。
5. 在群里 @ 机器人说「记住：我们每周三发版」，再另起一条 @ 它问「我们哪天发版？」，它会用上刚才的记忆。
6. 让它做件需要几步的事，比如「@机器人 读一下 https://… 和 https://… 这两篇，对比一下」，卡片上会列出每一步；中途可以点「停止」。

机器人如果也在告警群等业务群里，只要不把那些群加进白名单，它在那里被 @ 也不会回应。

部署时：

```bash
npm run build
npm start
```

线上那台服务器是自动部署的：代码合并到 main 以后，同步到公司 GitLab，流水线在服务器上测试、更新、重启，起不来自动退回上一版。怎么走的、怎么设置、怎么回滚见 [deploy/README.md](deploy/README.md)。

| `MCP_<名字>_THINKING` | 否 | `on`（默认）或 `off`。调过这个服务的工具（包括读剧本）以后，这次任务后面几轮打开思考：排查线上问题每拿到一次结果都要想清楚下一步查什么。只在 `MODEL_THINKING` 关着时有影响 |
| `KNOWLEDGE` | 否 | 团队经验库，默认 `on`，填 `off` 关掉（回答前不查，也没有起草经验的工具） |
| `KNOWLEDGE_BITABLE` | 否 | 用哪张多维表格存经验，填打开那张数据表时浏览器里的链接（`https://xxx.feishu.cn/base/…?table=tbl…`）。不填时第一次保存经验时机器人自己建一张，记在 `<DATA_DIR>/knowledge/bitable.json`。指定的表机器人不管共享：谁能看、谁能改在飞书里自己设，白名单群和写权限名单变了也不会跟着改。机器人自己建的表不要填在这里（填了就不再按名单撤销权限，而这张表只有机器人能管协作者），见下面「经验库表格的记录文件」。指定的表缺哪些列，机器人第一次写入前自动补上 |
| `KNOWLEDGE_EMBEDDING_MODEL` | 否 | 经验库按意思检索用的向量模型，和主模型用同一个服务和 Key。百炼默认 `text-embedding-v4`，别家服务不配时只按关键词检索，填 `off` 也只按关键词 |
| `ANNOUNCE` | 否 | 更新通知，`on`（默认）或 `off`。部署新版本重启后，把 `RELEASE_NOTES.md` 里还没发过的版本发到群里 |
| `ANNOUNCE_CHAT_IDS` | 否 | 更新通知只发这几个群（chat_id，逗号分隔，要在 `FEISHU_ALLOWED_CHAT_IDS` 里）。不填就发白名单里的所有群 |
| `ANNOUNCE_LINK` | 否 | 产品功能说明的链接，要是 `https://` 地址。更新通知卡片上「产品功能说明」按钮打开它；有人 @ 机器人问「你能做什么」「想看全部功能」时，功能卡片最下面的「产品功能说明」按钮、模型的回答里也用它（`ANNOUNCE=off` 时也用）。不填就没有按钮，回答里也不附链接 |
| `DOCS_LINK` | 否 | 文档中心的链接，要是 `https://` 地址。更新通知卡片最下面「文档中心」按钮打开它（在「产品功能说明」旁边）。`RELEASE_NOTES.md` 某一版里单独一行写 `[按钮上的字](文档中心)` 或 `[按钮上的字](功能说明#小节)`，卡片上按钮就放在这一行的位置（跟在那个新功能下面），地址换成 `DOCS_LINK`、`ANNOUNCE_LINK`；也可以直接写 `https://` 地址。不填就没有这个按钮 |
| `DATA_DIR` | 否 | 数据目录，默认启动目录下的 `data`。群记忆存在 `<DATA_DIR>/memory/<chat_id>.json`，卡片里的回答按话题记在 `<DATA_DIR>/card-answers/<chat_id>/<话题第一条消息 id>.json`（每个话题最近 60 条，读话题历史用；半年没再记新回答的话题文件自动删掉），每个群最近 30 个话题的问答记在 `<DATA_DIR>/recent-threads/<chat_id>.json`（`chat_recent_threads` 用） |

**换模型**：百炼上的其他模型（千问其他型号，以及 Kimi、GLM、DeepSeek 等第三方模型）只需改 `MODEL_ID`，模型 ID 在百炼控制台的模型列表里查。要换到别家的 OpenAI 兼容接口，再改 `MODEL_BASE_URL` 和 `MODEL_API_KEY`。

## 常见问题

- **启动时报「连接飞书失败」**：App ID / Secret 不对，应用还没添加机器人能力、没发布版本，或者服务器访问不了 `open.feishu.cn`（内网服务器需要放行出网）。
- **@ 了机器人没反应**：先看终端日志。出现 `忽略白名单外的群` 说明这个群还没加进 `FEISHU_ALLOWED_CHAT_IDS`。什么日志都没有的话，检查长连接订阅和 `im.message.receive_v1` 事件是否已添加并发布、机器人是否在群里，以及有没有别的程序（比如调试用的监听脚本，或同一个应用的其他服务）也用这个应用连着长连接：飞书只把每个事件推给其中一个连接，事件会被分走。
- **回复「连不上模型服务」**：运行环境访问不到 `MODEL_BASE_URL`，检查内网服务器的出网策略。
- **回复「模型服务返回错误」**：多半是 `MODEL_ID` 写错或该模型没开通，终端日志里有模型服务返回的原始报错。
- **回复「被内容审核拦下」**：百炼对输入输出做内容审核，换个说法即可。
- **回复「要看的内容超出了模型一次能读的长度」**：模型服务说输入太长，机器人已经把较早几轮的工具结果压到只留开头、重试过（日志里有「模型说输入太长」），还是放不下。默认的 `qwen3.8-max` 一次能读约 99 万 token，一般撞不上，换成上下文小的模型时容易遇到。把问题拆小，或者说清楚服务和时间范围再问。
- **追问时机器人不记得话题里其他人说的话**：没开 `im:message.group_msg` 权限，启动后第一次追问时日志里会有「读取话题历史失败」。开通权限并发布新版本即可，不用重启。
- **点「停止」提示出错**：没在回调配置里用长连接订阅 `card.action.trigger`，或者配了没发布新版本。
- **回答又另外发了一遍、卡片里没有回答**：卡片即回答没生效，日志里找「建流式卡片失败」：多半是没开 `cardkit:card:write` 权限，或者开了没发布新版本。之后 10 分钟内都用老办法，再自动重试。回答太长（超过 4000 字）时卡片里只放开头、全文另外发，这是正常的。
- **进度卡片没出现，但回答正常**：日志里会有「发送进度卡片失败」和飞书返回的原因。常见原因是飞书客户端版本太旧，不支持卡片 JSON 2.0。
- **机器人说没有文档的权限**：飞书里应用默认看不到任何文档。让文档所有者在文档右上角「…」→「更多」→「添加文档应用」里加上机器人，或者把文档分享给机器人所在的群（添加群为协作者）。知识库页面同理。
- **机器人说缺少飞书应用权限**：按回答里给出的权限名（飞书的报错里带着申请链接）在开发者后台开通，然后发布新版本，不用重启。
- **搜索失败或没有来源**：搜索走百炼原生接口（和 `MODEL_BASE_URL` 同一个域名的 `/api/v1/...`），要能访问它；模型要支持联网搜索（千问 Max、Plus 等支持，第三方模型一般不支持）。千问 3.5 以后的多模态模型要走多模态接口，第一次报「url error」后会自动换过去；两个接口都报「url error」时，设 `WEB_SEARCH_MODEL=qwen-plus` 试试。回答里说「没有返回搜索来源」时，多半是模型没真的去搜，换 `WEB_SEARCH_MODEL` 试试。
- **回复慢，想知道时间花在哪**：日志里每轮模型调用记一行（`模型第N轮 用时 输入 输出 其中思考 → 调用哪些工具 / 给出回答`，单位是 token），每次工具调用记一行用时，工具失败时记下原因。时间多半花在模型输出上：回答或写进文档的内容越长越慢；「其中思考」很大说明模型开着思考模式。
- **代码仓库访问不了**：启动日志里每个仓库有一行「代码仓库 xxx：能访问，角色 Developer」或「代码仓库 xxx 访问不了：原因」。GitLab 对看不到的私有项目也回 404，所以「找不到项目」多半是令牌的账号不是项目成员、用了别的项目的项目访问令牌，或者 `CODE_REPOS` 里的路径和网页地址栏里的不一样。
- **机器人说「回答里引用的文件、行号或提交号在查到的代码里找不到」**：模型引用了这次工具结果里没有的文件（包括 `/app/src/x.ts:99` 这样的绝对路径）或提交号，打回重做一次后还是这样，回答就没有发出，日志里有「还是引用了没查到的代码位置，没有发出」和那些路径。多半是问到的服务代码不在 `CODE_REPOS` 里：要让机器人读这个服务的代码，请这个仓库的 Maintainer 把机器人账号加成 Developer，再把仓库加进 `CODE_REPOS` 并重启。
- **代码仓库工具报 git 失败**：服务器要装 git（2.31 以上），并能访问 `GITLAB_URL`（GitLab 在公司内网时，服务器要能连进去）。令牌要能访问 `CODE_REPOS` 里的项目并推分支、开合并请求。GitLab 用的是自签名证书时，把公司的根证书放到服务器上，在 `.env` 里设 `GIT_SSL_CAINFO` 和 `NODE_EXTRA_CA_CERTS` 指向它。每个话题拉的代码在 `data/workspaces/<话题>/` 下，3 天没用自动删掉。
- **aiops 工具没出现**：启动后日志里应该有一行「MCP aiops：已连上 …，服务端 29 个工具，开了 20 个」。看到「MCP aiops 连不上：HTTP 404，令牌或地址不对」时检查 `MCP_AIOPS_TOKEN` 和 `MCP_SERVERS` 里的地址（aiops 令牌不对时回 404，不是 401）；其他原因多半是服务器访问不了 aiops 的地址。连不上时机器人照常回答别的问题，按 30 秒、1 分钟、2 分钟、5 分钟的间隔自动重试。每次 aiops 调用在日志里记一行「MCP 调用 aiops.工具名 chat=… sender=… 参数=… 结果=…字 用时=…」。
- **机器人说看不到图片**：日志里有「识别图片 0/1 张」时，往上找原因。「下载图片失败」多半是没开 `im:resource` 权限（开通后发布新版本，不用重启）；「识别图片失败」多半是 `MODEL_VISION_ID` 指的模型不能看图，换成 `qwen3-vl-plus` 这类视觉模型试试。日志里是「没配看图模型」时，检查 `MODEL_VISION_ID` 是不是设成了 `off`。一次提问最多识别 4 张图（提问里的在前，然后是话题里最近的），识别过的图会记住，话题里追问时不再重新识别。
- **读取网页失败**：服务器要能访问公网。出于安全考虑，工具不会访问内网、本机和云服务器元数据地址。
- **机器人在话题里插嘴**：它只在回答过的话题里接话，判断不是对它说的就不回；判断错了，在话题里说「只在 @ 我时回」，这个话题就不再跟（日志里有「跟聊：话题里说了只在 @ 时回」，记在 `data/follow.json`，重启后也不跟）。整个关掉设 `FOLLOW_THREADS=off` 后重启。日志里每条要判断的消息都有一行「跟聊：没 @ 的话题消息…」，看得到它为什么回或不回。
- **机器人在群里主动插话太多**：在群主界面 @ 它说「别主动插话」，这个群就停了（记在 `data/proactive.json`，重启后照样停着），「可以主动说话」再打开。想给每小时回几次设个上限，就填 `PROACTIVE_MAX_PER_HOUR`（1～60，不填不限）；彻底关掉就把群从 `PROACTIVE_CHAT_IDS` 里去掉后重启。日志里每条判断过的消息有一行「主动接话：接一句/不接」，填了上限、到了上限时有一行「这一小时已经主动回了 N 次」，每小时判断满 120 条时有一行「这一小时已经判断了 120 条」。
- **机器人在群里不主动说话了**：先看日志有没有「这个群先不看了」：它上次说话以后群里发了 200 条、或者 10 天没人 @ 它，就先不看这个群（和 Claude Tag 一样），在群里 @ 它一次、它回了就接着看。日志里「最近没被 @ 时开口有人理=0/5」这种，是它主动说的话老没人理，它自己少说了。
- **定时任务没跑、跑晚了**：启动日志里有一行「定时任务：群里 @ 机器人说…就能建」，看到「定时任务：已关闭」就是 `SCHEDULED_TASKS=off`；文件里有任务时还有一行「定时任务：读出 N 个等着到点的、M 个暂停的」。到点时日志有「定时任务：T3 到点了」；跳过、错过、连着失败暂停的各有一行说明原因。群里 @ 它「这个群有哪些定时任务」能看到每个任务下次什么时候跑、上次跑得怎么样。`data/schedules.json` 不要在机器人运行时手改（它会被程序覆盖），要改先停机器人。
- **@ 了有时回有时不回**：多半是同一个飞书应用还有别的程序连着长连接，把一部分事件分走了。补漏轮询会把这些 @ 补上，日志里出现「补漏：事件没送到」就是这种情况，补上的多了群里还会收到补漏报警。要根治，就找到并停掉那个程序，或者给机器人换一个专用应用。日志里的「事件晚到，这条已由轮询处理」说明事件只是推送慢，不是被分走，不算在报警里。
- **经验库表格的记录文件**：机器人自己建的经验库表格记在 `data/knowledge/bitable.json`，里面是表格在哪、共享给了哪些群和人。同一个目录下的 `issued.json` 记着发过的最大经验编号。换服务器或重新部署时，连同 `data/` 整个拷过去。这个文件丢了，机器人就不知道以前共享给了谁，以后移出名单的群和人也撤不掉；而这张表设成了只有机器人能管协作者，别人在飞书里也改不了。真丢了的话，不要把旧表填进 `KNOWLEDGE_BITABLE` 接着用：让机器人新建一张（`KNOWLEDGE_BITABLE` 留空），把旧表里的经验复制过去。旧表还共享着以前的群和人，机器人也管不了它了。
- **群记忆存在哪、怎么恢复或清空**：每个群一个文件 `data/memory/<chat_id>.json`（`DATA_DIR` 可改位置），只有运行程序的用户能读写。每天的备份在 `data/backup/memory/<日期>/`，和记忆在同一块盘上，防的是误删、写坏，不防整块盘坏掉。恢复一个群：先停服务，把备份里的 `<chat_id>.json` 复制回 `data/memory/`，再启动（程序运行时会缓存记忆，不停服务直接复制会被覆盖）。清空一个群的记忆就停服务、删掉它的文件、再启动。记忆的增删改会记在日志里（`群记忆 chat=… 新增 #3 操作人=…`），只记编号和操作人，不记内容。
- **经验库回答前总是「查到」不相干的、或者该查到的查不到**：在机器人目录下跑 `npm run build && npm run eval:knowledge`，拿各群最近话题里问过的问题去团队经验库检索，列出几档门槛下有几个问题查到了、每个问题最像的 3 条和分数（现在的门槛是语义相似度 0.6，或者关键词、错误码、告警名对上 2 个）。也可以给一个提问文件：`npm run eval:knowledge -- 提问.txt`，一行一个，行尾写「=> K3」或「=> 无」标上应该查到哪条，会多算查对了几条。只读：不改表格、不调 aiops、不发消息，机器人开着也能跑。输出里有提问原文和经验标题，贴给别人前看一眼。
- **日志里出现「群记忆文件损坏」**：程序把坏文件改名成 `…json.corrupt-时间戳` 留着，这个群从空记忆重新开始，可以手动从坏文件里把内容找回来。

## 当前限制（后续阶段解决）

- 群记忆只在机器人回答问题时写入。它只在被 @ 时看群里之前半小时的聊天、在它回答过的话题里看追问，以及在开了主动接话的群里看群主界面的新消息，不会自己去翻群里别的聊天记录。主动接话回一句时不调工具，只能拿群记忆、刚才的聊天和开口前查到的经验回答，或者问一句要不要帮忙。
- 记忆超过提示词的字数上限（约 8000 字）时只列最近更新的，更早的靠关键词查找，还没有向量检索。每个群最多 300 条。
- 群里任何人都能让机器人记住或忘掉东西，权限控制在阶段 5 做。
- 飞书文档只支持新版文档（docx）和知识库里的新版文档；旧版文档、电子表格、多维表格还读不了，写入时图片会变成链接。
- 机器人能读写所有给它开过权限的文档，群里任何人都能让它读其中任何一篇；配了 `WRITE_ALLOWED_USERS` 后只有名单里的人能让它改。按群限制范围在阶段 5 做。
- 联网搜索只支持百炼；换成别家模型服务时搜索自动关掉。
- 代码仓库支持 GitLab 和 GitHub；机器人推代码前只编译检查（`BUILD_CHECK`），不运行代码和测试（要隔离的运行环境，阶段 5 做）。合到 master、prod 这类只许维护者合并的分支要人审查后点。没配 `WRITE_ALLOWED_USERS` 时，群里任何人都能让它改 `CODE_REPOS` 里的仓库并开合并请求。
- 团队经验库所有白名单群共用，按群控制能看哪些经验在阶段 5 做。确认卡片的草稿存在内存里，机器人重启后旧卡片点了提示失效，要重新让它起草。确认卡片要求同一个飞书应用只跑一个机器人进程：多跑一个的话飞书会把卡片回调分给另一个进程，它不认识这张卡片，会把卡片改成失效（@ 消息和「停止」按钮也会被分走）。直接在多维表格里改的排查经验不会同步到 aiops 经验库，要改的话让机器人起草新的一条替换旧的。
- MCP 只支持 HTTP（Streamable HTTP）服务，还不能接 stdio 类的本地 MCP 服务。模型只能用 aiops 的只读工具；存经验、归档经验只能经确认卡片，由写权限名单里的人点确认。白名单里的群都能用 aiops，按群限制能用哪些 MCP 服务和工具在阶段 5 做，加第二个群之前要先有这一项。
- 单聊暂不响应，只处理群里 @ 机器人的消息、它回答过的话题里的追问和开了主动接话的群里的消息。
- 主动接话每小时的次数、当天有没有提示过怎么关记在内存里，重启后重新算。
- 停机那会儿话题里没 @ 的话，重启后不补着判断（补漏轮询只看启动以后发的）；`data/follow.json` 读坏了时，重启前跟着的话题要再 @ 一次才接着跟。
- 去重记录、进行中的任务和本地记下的问答都在内存里，重启后清空（群记忆在磁盘上，不受影响）；重启时进行中的任务会被标成「已停止」。多开几个实例也不会重复回答，飞书只把每个事件推给其中一个连接。
- 回答不是流式输出，模型想完才一次发出。
- 定时任务只按北京时间；到点跑的不改代码、不开合并请求，改文档只能追加到建任务时贴了链接的那一篇，别的只能新建。按群限制谁能建、能用哪些工具在阶段 5 做。
